# Migration prompt: move the iLearn/iSolve site to Firebase Hosting (ilearnhub.web.app)

Copy everything below the line into a new Claude Code session opened in the repo.

---

ROLE
You are a careful DevOps engineer moving a live school learning site from GitHub Pages to Firebase Hosting with NO data loss and NO downtime for students. Work in phases. After each phase, show me the evidence (command output, counts, screenshots) and WAIT for my "go" before the next phase. Never delete or overwrite anything in the old setup. Never commit or push unless I say "commit and push".

GOAL
1. The site is served from https://ilearnhub.web.app (Firebase Hosting site ID `ilearnhub`).
2. All stored data comes with it: Firebase Auth users (logins keep working with the SAME passwords), Firestore data (users, progress, exam attempts, live bookings, timetables, groups, feedback, etc.), Storage files if any, security rules and indexes.
3. The old site (GitHub Pages) keeps working until I approve the cutover, then redirects to the new URL.

CURRENT SETUP (read the repo to confirm, do not assume)
- Static site, repo `ashraf2k/-practice-quiz`, branch `main`, GitHub Pages.
- Firebase Auth (email/password, Google) + Firestore. Config is in `firebase-init.src.js`, bundled to `firebase-init.js` (rebuild steps in my notes: esbuild, then bump `?v=` in the html files).
- `firestore.rules` is published manually. A Cloudflare Worker (`worker/`) handles Telegram notifications and has an origin allowlist.
- CSP is generated by `node tools/csp.js`; service worker `sw.js`; PWA manifests.
- Timezone Asia/Riyadh. Owner: Mr. Ashraf.

PHASE 0 - DISCOVERY (read-only)

- Explain the trade-off: (A) needs no data copy, users and data stay exactly as they are, only a new Hosting site `ilearnhub` is added. (B) needs a full export/import of Auth and Firestore. Recommend A unless I say otherwise.
- List every place that hard-codes the old domain (grep for `github.io`, `ilearncs`, `ashraf2k`, absolute URLs in html/js/manifests/sw/worker CORS/CSP/sitemaps/emails/Telegram links).
- Check that the site ID `ilearnhub` is available (`firebase hosting:sites:create ilearnhub`). If taken, propose 3 alternatives and stop.
- Confirm Firebase CLI is installed and I am logged in (`firebase login`, interactive, I do the login myself; never ask me to paste passwords, tokens or keys into the chat, and never write them to files in the repo).

PHASE 1 - BACKUP FIRST (before touching anything)
- Export Firestore to a Cloud Storage bucket: `gcloud firestore export gs://<bucket>/backup-YYYYMMDD`, then download a copy.
- Export Auth users with password hashes: `firebase auth:export auth-users.json --format=json --project <old>`. Note the project's hash parameters (Console > Authentication > Users > three dots > Password hash parameters). Keep these files OUT of git (add to .gitignore), and tell me where they are stored.
- Back up current `firestore.rules`, `firestore.indexes.json`, Storage rules, and a full `git bundle` of the repo.
- Write down document counts per collection and the Auth user count as the "before" numbers.

PHASE 2 - NEW HOSTING SITE (no data yet if option A)

List each change as a checklist and tick them off.

PHASE 3 - DATA (only if option B, new project)

- Import Auth with hashes: `firebase auth:import auth-users.json --hash-algo=SCRYPT --hash-key=... --salt-separator=... --rounds=8 --mem-cost=14 --project <new>` using the real parameters from the old project. Verify one test login with a known password.
- Import Firestore: `gcloud firestore import gs://<bucket>/backup-YYYYMMDD` into the new project (grant the service account access to the bucket).

PHASE 4 - VERIFY ON THE PREVIEW (with me)

PHASE 5 - CUTOVER (only after I say "go live")

- Replace the GitHub Pages site with a redirect page to `https://ilearnhub.web.app` (keep the repo for history). Add a visible notice for students already logged in on the old URL (their localStorage progress does not move between domains: make sure unsynced progress is pushed to Firestore first, or warn them to open the old site once and sync).

PHASE 6 - AFTER GO-LIVE

- Keep the old project and GitHub Pages untouched for 30 days as a rollback.
- Write a one-page ROLLBACK.md and a RUNBOOK.md (how to deploy, rebuild firebase-init.js, publish rules, restore a backup).

HARD RULES
- Ask before any destructive command (delete, overwrite, `--force`). Never run import against a non-empty production project without showing me the plan.
- No secrets in the repo, chat, logs or screenshots. Use interactive login or a service-account file kept outside the repo.
- Every phase ends with: what was done, evidence, what could go wrong, next step. Do not skip phases.
- If anything is ambiguous (project ownership, billing plan, region), ask me ONE short question instead of guessing.

## My recommendations (not part of the prompt)

1. **Stay in the same Firebase project if you can (option A).** A project can hold several Hosting sites. You only add the site `ilearnhub`: no export/import, no password-hash risk, no student re-registration. This is the safest and cheapest path.
2. **Check that `ilearnhub` is free first.** Site IDs are global; if taken, you get `ilearnhub-xyz.web.app`.
3. **Billing:** Hosting + Auth + Firestore are fine on the free plan for a school-size site, but scheduled backups and Cloud Functions need the Blaze (pay-as-you-go) plan. Set a budget alert.
4. **Run the old and new sites in parallel for a week**, then redirect. Progress stored only in a student's browser (localStorage) does not follow them to a new domain, so announce the move and ask students to open the old site once.
5. **Do the move outside exam weeks and live-session hours.**
6. **Later:** attach a custom domain (e.g. ilearnhub.com) to Hosting so you never have to change URLs again.
7. **Rotate nothing, but restrict:** after the move, restrict the Firebase web API key to the new domain and keep the `firestore.rules` publish step in the runbook.
